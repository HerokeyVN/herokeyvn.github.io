## Five required thread states

Capture every state at desktop and mobile, for ten final images:

1. `before`: Hero approach exists but no glyph contour is visible.
2. `entry`: first routed glyph is actively drawing.
3. `mid`: roughly half the headline route is complete.
4. `exit`: final routed glyph is actively drawing or has just completed.
5. `after`: all glyph contours/connectors are complete and continuation toward Experience has begun.

Store final files as:

```text
design-explorations/screenshots/glyph-trace/
  desktop-before.png
  desktop-entry.png
  desktop-mid.png
  desktop-exit.png
  desktop-after.png
  mobile-before.png
  mobile-entry.png
  mobile-mid.png
  mobile-exit.png
  mobile-after.png
  README.md
```

Move experiments into an explicitly named `diagnostics/` folder or remove only files generated by this task. Never delete user-owned reference material.

## Determining capture positions

Do not guess positions from section offsets alone. Inspect runtime state:

- `before`: all `[data-glyph-contour]` paths have `visibility:hidden`.
- `entry`: the earliest route contour has a partial dash.
- `mid`: accumulated visible CSS-pixel length is nearest 50% of headline weight.
- `exit`: final route contour is partial.
- `after`: all contours have `strokeDasharray:none`; visible connectors have approximately zero offset.

Record every capture's `scrollY` in the screenshot README.

## Static composition review

- The outlined phrase dominates the About composition.
- All letters read as one phrase, not fragmented decorative marks.
- Red supports hierarchy instead of overpowering the ivory outline.
- Same-line connectors occupy deliberate negative space.
- No connector forms an accidental bar across multiple glyphs.
- The hidden line break reads naturally; no diagonal slash joins lines.
- Hero-to-About and About-to-Experience continuations feel related.
- The central Hero aperture remains available for a future 3D model.
- Completed Hero path segments reach their transformed endpoints without floating gaps.
- The Hero-to-About boundary uses a short deliberate handoff, not a long horizontal or viewport-edge cable.
- Exactly one responsive Hero path set is visible, including at breakpoint-adjacent widths.

## Motion review

Perform these manually at both primary viewports:

1. Slow forward scroll through the full headline.
2. Slow reverse scroll back to the Hero.
3. Rapidly alternate direction three times during one contour.
4. Jump directly to `#experience`, then return to `#about`.
5. Resize while stopped at mid-trace.
6. Reload at the resized viewport.
7. Enable `prefers-reduced-motion: reduce`.

For Hero-to-About work, record normal-motion forward and reverse scroll at 1920×927 and 390×844. Inspect the recordings frame by frame. The required sequence is: attached Hero tail → attached short seam handoff → fully hidden travel → endpoint re-entry on the first glyph. Static screenshots cannot approve this sequence.

Reject the implementation if:

- the endpoint jumps across the screen;
- completed contours erase out of order;
- a contour starts before the preceding segment reaches its junction;
- resize leaves paths offset from HTML outlines;
- line wrapping changes but connectors use the old route;
- reverse state differs from forward state at the same position;
- the trace finishes after the headline leaves the viewport.
- a completed boundary handoff remains exposed after its marker disappears;
- the handoff and first glyph are visible simultaneously;
- a stroke disappears in uncovered empty space instead of behind the header, outside the viewport, or behind an existing mask;
- document-space endpoints match but the screen recording still reads as separate Hero, edge-stroke, and glyph animations.

## Readability and collision review

Protected elements include:

```text
p, a, button, nav, .initiative-card, .skill-row, .education
```

The collision test samples global paths every 4 CSS pixels with a 6-pixel safety margin. Keep that check, then manually inspect near misses, tangencies, and strokes that visually merge with rules or underlines.

## Automated validation

Fast iteration:

```bash
npm run check
npx playwright test tests/portfolio.spec.ts -g "continuous thread system|generated Syne contours|direct navigation and resizing|full glyph trace"
```

Final validation:

```bash
npm run build
npx playwright test
```

Required assertions:

- no console or page errors;
- no axe-core violations;
- essential content works without JavaScript;
- no canvas or Three.js dependency;
- full glyph/contour counts are correct;
- geometry stays aligned after resize;
- global thread avoids protected content;
- scroll progress reverses cleanly.

Do not fix a flaky geometry test by increasing timeout or relaxing a multi-pixel tolerance until logs prove runtime geometry is correct and only test scheduling is wrong.
